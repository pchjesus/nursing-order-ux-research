## 3. 임상적으로 미확인된 사항
- 실제 nU의 간호처방 범위·검색 구조·내부 코드·권한·업무 순서.
- 간호사가 어떤 조건에서 직접 등록/수행/기록 가능한지.
- 반복 처방의 같은 항목 판정, 보류/취소/연기의 의미, 실제 수행과 기록의 관계.
- nU 내부 화면 등을 적법하게 검토할 수 있는 범위.

## 5. 2026-10-10 기능 시뮬레이터 제작에 따른 잠정 해결/보류
- **OPEN-01 기능 시연 방식 반영:** 사용자가 직접 간호활동 선택 → **임시저장** → 로그인된 동일 가상 계정의 PIN **재인증 후 가상 확정**. 독립된 2차 검사자/실제 인증 아님.
- **OPEN-05 시범 선택 완료:** ACT 38개(구분이 잘 되는 유사 항목 + 여러 환자 시나리오). 후보 원본 315건은 그대로 보존.
- **OPEN-06 임시 UI 적용:** 좌측 모의 계정/환자, 업무 단계별 탭, 임상 목적 분류. **고정된 최종 UX 결정이 아님**.
- **OPEN-02/03/04**는 여전히 UX·임상 규칙 검증 필요. 특히 그룹화/상태/예정횟수의 세부 정책 미확정.
- 실제 등록자/수행 권한·전자서명, 독립적인 교차 확인, 서버 인증 및 다중사용자 기록 관리 여부는 미래 논의.

## 7. 2026-10-10 추가 개발 결정: 세 시스템은 당분간 독립 개발

- **간호처방 v0.2.2 [구현]:** 가상 환자별 Kardex·간호처방지 접이식 **조회 패널**(임시 UI)을 추가. 실제 nU 재현/임상 지침 확정이 아님.

## 8. v0.2.5 — 예정 조회의 잠정 구현과 남겨둔 선택
- **잠정(최종 UX 승인 아님):** 새 합성 처방의 선택적 ISO 예정 슬롯(일회성·간격 반복·조건부)을 표시하고, 모의 수행 사건에 슬롯 ID를 명시적으로 연결. 기존 빈도 선택·기록 정책·정체성은 변경하지 않음.
- **OPEN-03 일부 기술 검증:** 예정 횟수(미정 가능)/수행 사건 수/기록 수를 분리하는 기술 구현만 완료. 실제 병원의 누락·완료·보류·정정 상태 판정 규칙은 아직 미확정.
- **향후 사용자 결정 필요:** 개별 슬롯/근무조 시간창/조건 기반 예정 중 실제 기본 표현, 연기·보류·취소·정정의 입력 권한과 이력 정책, 지속 반복 처방의 종료/수정·타임존 정책.
- 서버·실제 병원·타 저장소 통합과 사용성 평가로 확장하지 않음.

## 9. v0.2.6 — 예정 슬롯 상태 변경 시연 (업무 규칙 미승인)
- 교육용 가상 처방에서 **슬롯의 보류·재개·취소·연기**만 구현. `confirmed` 처방 및 아직 모의 수행과 연결되지 않은 슬롯에 한정; 기존 ID/최초 시각/수행·기록 원본 보호.
- 보류·취소·연기를 실제 병원 용어의 최종 정책으로 승인한 것이 아니다. 취소한 슬롯은 **이번 데모에서만 최종 상태**로 취급.
- **미결정:** 처방 전체 보류/재개/취소 권한과 확인자, 취소 후 복원·연기 정의, 시간창·근무조별 관리, 실제 수행된 슬롯의 정정, 감사 이벤트의 법적 효력. 실제 임상적 타당성과 사용자 결정 전까지 보류.
- v0.2.5 이후 신규 문서 `CLINICAL-VALUE-REASSESSMENT`와 합성 사용성 파일럿은 유지·우선 반영; 앱 추가 확장은 문제 검증 Gate 0 우선.
