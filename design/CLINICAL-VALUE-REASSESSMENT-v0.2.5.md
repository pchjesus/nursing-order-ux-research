# 간호처방 UI/UX 개선 — 전방위 타당성·위험·개발 우선순위 재검토

> 작성: 2026-10-10 | 기준: `pchjesus/nursing-order-ux-research` private/main `80a2d13e1d42d7d7e23fd1ad362a2768b720119d` / v0.2.5
> **문서 검토안(승인된 기능 명세나 임상 타당성 인증이 아님)**. 코드/UI/데이터/저장 정책을 변경하지 않는다.

## 1. 핵심 판단
- **문제 영역은 연구 가치가 높다**: 간호활동 검색·유사 항목 구별, 처방/예정/수행/기록의 오해 방지, 불필요한 전산 화면 이동 및 기록 부담.
- **본 앱의 임상적 유용성은 미검증**: 사용자 실습 관찰과 합성 시나리오는 의미 있는 문제 제기이나, 실제 nU의 간호처방 검색/상태 기능과 직접 비교한 증거가 없다.
- PRN 프로젝트처럼 기존 기능을 재개발할 위험을 줄이기 위해 **신규 구현보다 기존 기능 파악 → 문제 검증 → 작은 비교평가**를 먼저 진행한다.
- 제품·세트 세부 후보 추가, 전체 315항목 임상 매핑, 독립 인증·다중사용자 저장 및 타 앱 통합은 지금 확대할 이유가 부족하다.
- 간호처방 프로젝트의 가상 MVP는 보존. 실무에서 유용한 기능만 선택적으로 채택·검증한 뒤 다음 패치를 결정한다.

## 3. 업무·임상 관점에서 검증할 문제
1. **간호처방의 의미와 권한 먼저 정의**: 간호사 독립 활동, 타 직종 처방의 수행, 간호기록, 청구/재료 선택, 실무 체크리스트를 같은 '간호처방'으로 단정하지 않는다. 현재 `ACT/FOLLOW/MAT` 분리는 합성 개념이지 기관별 법적·운영상 분류가 아니다.
2. **검색·오선택**: 유사 명칭/코드/임상 목적을 구분하지 못해 다시 검색하거나 잘못 선택하는 실제 사례가 있는지 확인. 사용자의 기억·훈련 문제인지 화면 구조의 문제인지도 조사한다.
3. **처방 후 정보 파편화**: 개별 처방·예정·모의 수행·간호기록의 관계를 조회하며, '처방 1건/예정 3회/수행 1건/기록 0건'을 곧바로 누락으로 해석하지 않는다.
4. **업데이트 지연**: 규정의 정확한 이름/발행일/대상 화면/소관부서/검증·승인 절차/실제로 지연된 사례가 확보되기 전까지 시스템 결함으로 단정하지 않는다.
5. **과잉 입력·새로운 부담**: 추가 단계/버튼, 확인 절차, 세부 제품 선택, 화면 이동이 실제 사용자의 시간을 늘리는지 비교한다.

## 6. 정식 업무 검증용 짧은 질문지
1. 병원에서 '간호처방'으로 직접 입력할 수 있는 항목과, 의사 처방 확인·수행·간호기록은 각각 무엇인가?
2. 자주 찾기 어렵거나 잘못 고르기 쉬운 활동은 **어떤 차이 때문에** 혼동되는가? 기존 검색·필터/분류로 해결하는 방법은 있는가?
3. 새 간호사가 가장 오래 걸리는 단계는 검색, 선택 조건 확인, 등록, 반복 수행 체크, 기록 중 어디인가?
4. 동일 처방이 반복될 때 무엇을 횟수로 보며, 예정·수행·기록·중단·보류를 어떻게 표시하는가?
5. 현재 EHR에서 이미 제공하는 즐겨찾기/최근 처방/동의어/개별 상세/그룹·이력 보기는 무엇인가?
6. '최신 규정 반영 지연'이 무엇을 의미하며 실무에서 어떤 오류·우회작업·재확인 부담이 실제로 생겼는가?
7. 단순 UI 변경으로 해결되는 문제인가, 교육/권한/처방 사전/업데이트 프로세스의 문제인가?
8. 개인정보·기관 보안 정책을 지키면서 가상의 비교 과제로 실사용성을 평가할 수 있는가?

실제 환자/직원정보, 병원 내부 화면·코드/규정 원문을 승인 없이 수집하거나 외부 전송하지 않는다.

## 7. 가상 MVP 비교평가 계획
- **A 검색:** 유사 활동 세 가지 중 목표 상황에 맞는 항목 식별. 오선택·재검색·시간·도움말 의존도 측정.
- **B 구별:** 동일 코드의 가상 처방 2건에 서로 다른 부위/방법/빈도 설정. 화면 묶음과 개별 펼침의 원본 유지·차이 인지 평가.
- **C 상태:** 처방 1건, 예정 3회, 수행 1건, 기록 0건 같은 합성 반례. '누락'이나 '수행완료'로 성급히 판정하는지 평가.
- **D 환자:** 환자 전환·로그인 전환 시 검색/미등록 초안/저장 기록이 엉키지 않는지 평가.
- **E UI 부담:** 기존 MVP와 최소 정보 중심 대안의 클릭 수·화면 이동·오선택·주관적 업무부담 비교.

사전 정의된 성공지표, 비교대상, 테스트 참가자의 임상 경험 범위 및 질문지를 기록한다. 소규모 실험은 인과적 투약/환자안전 개선의 근거가 아니라 UX 탐색 결과로만 해석한다. 절대 시간 목표나 합격 수치를 임의로 확정하지 않는다.

## 8. 다음 개발 게이트
- **Gate 0:** 현장 업무의 정의, 실제 nU 기존 기능과 중복 여부, 핵심 불편의 발생 빈도/사례 확인. 미확인이면 UI 기능 확장은 보류.
- **Gate 1:** 실제 필요가 있는 1~2개의 가상 업무 과제와 불편의 원인을 명시.
- **Gate 2:** 이미 구현된 v0.2.5 기능으로 대안 UX 1개를 작은 범위에서 비교. 선택오류·업무 부담 증가 시 우선 보완.
- **Gate 3:** 검증된 요구에 한해 작은 UI/데이터 변경 승인, 기존 저장키·스키마/도메인/CI 보존 및 영향 검증.
- 통합 EMR, 정보 동기화, 권한/영구저장 구조 변경은 별도 검토 및 사용자 의사결정.
