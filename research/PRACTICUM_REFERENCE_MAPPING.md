# 학교 실습자료의 간호 시나리오·처방지 구조 참고표
작성: 2026-10-10 · **사용자 제공 학교 실습/평가 자료** 분석 · 향후 합성 시나리오 설계 원칙

## 1. 원본의 성격과 활용 제한
1. `icn 워크리스트.pdf` — **12쪽**. 제목별 술기 시나리오와 '처방 리스트' 및 간호 수행 과제 제시.
2. `2026사례기반 실무실습 사례자료.pdf` — **17쪽**. 일차별 실습 일정, 사례개요, `Kardex`, `Order Manage` 표, 수행 고려사항과 피드백 형식 제시.
3. 사용자 설명에 따르면 두 번째 자료는 실제 병원 처방지와 **유사한 형태**이며, **실제 nU의 현재 UI·데이터 명세 또는 처방 규칙이 검증된 자료가 아니다**. 이 프로젝트에서는 **UX 정보 구조와 합성 시나리오 작성 시 참고**한다.
4. 원본의 이름·등록번호로 보이는 식별자·병동 표시·처방코드·실제 약물 용량이나 병원 운영값을 데이터베이스·GitHub에 옮기지 않는다. 학생 교육자료 저작권 때문에 **원본 PDF·캡처·원문 표 전재는 하지 않음**.
5. 원본에 보이는 시술 지시는 평가 상황의 지시일 수 있으므로 병원별 실제 간호사 처방/수행 권한이나 안전 처방 프로토콜로 취급하지 않는다.

## 2. 파일별 확인한 페이지/구조
### A. `icn 워크리스트.pdf` (12쪽)
| 쪽 | 항목 제목 또는 범위 | 설계상 활용 가능한 정보 |
|---|---|---|
| 1 | 활력징후 측정 · 욕창/낙상예방 | 간호활동과 관찰/측정 지시가 공존, 처방 리스트 접근 |
| 2~4 | 피하주사 및 간이혈당 측정 | 혈당 측정(간호활동)과 약물 투여 지시(의사 약물처방 등)를 명확히 분리 |
| 5~7 | 피내·근육·정맥주사 | 시행 관련 간호행위와 주사제/주입재료·용량을 서로 다른 객체로 관리 |
| 8 | 통증관리·배액관 관리 | 통증 사정, 배액 확인, 처방 변경과 연계될 수 있는 사례 |
| 9 | 산소화·흡인 | 관찰→조건 판단→행위 확인 맥락의 모의 검증에 적합 |
| 10 | 수혈간호 | 혈액제제/투여 확인(연계 수행)과 관찰·교육 등 간호활동 구별 |
| 11~12 | 여성·남성 유치도뇨 | 행위·기구·배설 상태와 가상 환자 시나리오의 구분 |

**보이는 구조:** 술기 제목 → 가상 임상 상황 문단(과거력/상태/과제) → 환자 식별 요약 → 처방 리스트 표. 일부 표에는 구분·코드·처방명·횟수·경로·처방 시각·작성자 역할이 나타남.

### B. `2026사례기반 실무실습 사례자료.pdf` (17쪽)
| 쪽 | 확인한 요소 | 구조 활용 |
|---|---|---|
| 2 | 일차별 평가 술기와 평가 방법 | 시나리오별 과제/검증 항목의 매핑 |
| 4~5 | 1일차 수술 후 환자 사례 → Kardex → Order Manage | 환자 상황, 교대근무 인계요약, 개별 주문·정규/추가 항목 구분 |
| 7~8 | 2일차 정형외과 수술 후 환자 사례와 주문표 | 조건부 지시, 통증·상처·낙상예방 과제의 관련성 |
| 10~11 | 3일차 호흡/순환 환자 사례와 시간별 추가 처방 | 하나의 사례에 반복 등록/추가 시각이 있는 행, 검사·수혈·관찰 지시 혼재 |
| 13~14 | 4일차 신경계 환자 사례 및 순차 추가 지시 | 처방 변경 시간순 조회, 도뇨·배설·영양·검체 관련 영역 구별 |
| 15~17 | 고려사항·지식 평가·피드백 양식 | 사용자 수행과 평가기준을 주문 데이터와 구분 |

### 처방지 표의 정보 구조 예시 (5·8·11·14쪽에서 공통적으로 관찰)
- **환자 배경 / Kardex:** 사례 주제, 주요 상황/병력, 현재 관찰사항, 시간/조건에 따른 인계내용.
- **처방 섹션 헤더:** 정규/추가 등 구분, 작성 날짜·시각, 처방자 표시.
- **처방 행:** 구분(예: 전달·투약·PRN·검사), 처방코드, 처방명·지시문, 1회 용량/1일 수량/횟수(의약품·영양 등 항목에 해당), 경로·용법, 1회 수량, 처방 시간(AM/PM 등), 처방의사.
- **텍스트 지시:** 표의 다수 행이 약물 데이터가 아닌 관찰·간호·조건·보고 문장. 이를 일괄 의사 약물처방 또는 독립 간호처방으로 변환하지 않음.
- **이용 가치:** 같은 환자에게 시각별로 생성된 여러 요청/지시와 그에 대응하는 간호행위 후보를 **나란히 읽되 출처와 주체는 구분**하는 정보 구조.

## 3. 교육자료 형식 → 미래 합성 시나리오 구조 (제안)
| 학교 자료의 정보 덩어리 | 합성 시스템 엔터티 후보 | 혼동하지 말아야 할 경계 |
|---|---|---|
| 사례 개요/현재 병력/병상 | `Patient` + `Encounter/AdmissionContext`(향후) | 환자 신원과 입원 에피소드 별도 |
| Kardex의 요약/관찰 계획 | `HandoverSummary`(합성 인계 정보) | 독립 처방의 생성·확정 이력 아님 |
| 정규/추가 구역과 시각 | `OrderSection` 또는 주문 목록 표시 그룹 | 섹션 분류는 원본 주문의 고유 ID가 아님 |
| 약물명/용량/경로/시간 | PRN 앱의 `MedicationOrder` | 간호 처방에 약물 용량을 자동 복사하지 않음 |
| 간호 관찰/처치 지시 | `NursingOrder` 또는 `ServiceRequest`의 연관 후보 | 처방권한 미검증; 시나리오 문서에서 출처/상태를 먼저 정의 |
| 검사 요청·혈액배양/소변배양 | `ServiceRequest`, `Specimen`, `Container` | 검사=검체=채취용기=검체채취행위 아님 |
| 드레싱 등 간호행위 | `NursingActivity` / `Procedure` 관련 후보 | 상황별 독립 활동 vs 의료진 요청 기반 구별 |
| 수액 세트/카테터/채혈관 | `Material/Device/Container` | 물품 존재가 등록된 처방 또는 수행 완료 의미 아님 |
| 평가 과제/학생 피드백 | `SimulationTask` / `EvaluationCriterion`(미구현) | 환자 기록과 섞지 않음 |

## 4. 향후 4명 가상 환자 개발 시 참고할 시나리오 템플릿
기존 간호처방 환자 4명과 PRN 환자 4명은 **이번 작업에서 전혀 수정하지 않음**. 차후 별도 승인 시 아래 구조로 **새 합성 사례**를 설계하는 데 활용:
1. **수술 후 관리 사례:** 간호사정, 상처·배액관 상태, 독립 간호중재 및 의사약물처방/연계 수행 분리.
2. **정형외과 수술 후 이동지원 사례:** 통증 관찰, 낙상예방, 부위별 드레싱 및 동작 제한 등 확인 전제.
3. **호흡/순환 모니터링 사례:** 기도/산소 관련 관찰과 검사 요청, 검체/기구, 의사 투약 지시 구별.
4. **신경계·배뇨/영양 관리 사례:** 의식/피부 관찰, 도뇨·검체채취·영양지원 등 서로 다른 객체.
- 각 예제는 **환자 ID(가상), admission/context ID, 상황 텍스트, 주요 간호 목표, 개별 처방/지시 작성 주체, 상태, 생성 시각, 수행 시각/기록 시각, 관련 외부 주문 ID(있을 때만)**를 독립 필드로 가진다.
- '의사 처방 생성 → 간호처방 자동 생성'을 기본 시나리오로 강제하지 않음. 독립 간호활동과 의사 지시 연계 시나리오를 각각 포함.
- 약물 용량·시술 간격·수혈 조건은 **원본 교내 평가 지시를 임상 권장사항으로 재사용하지 않음**. 임상 실증 없이 기능 테스트 데이터로 표현할 경우 비임상·검증 전임을 명시.

## 5. 안전/저작권 및 검증 기준
- GitHub에는 학교 제공 PDF를 올리지 않는다. **자료의 표 구성·구분 개념과 쪽수만 기록**한다.
- 실제 인물/환자 이름, 차트 번호, 병원 내 고유 처방코드를 전사하지 않는다.
- '예시 처방'은 시나리오의 가상 사건이지 실제 처방 실행 지시가 아니다.
- 추후 도메인 계약에는 source_reference_type=`school_practicum_layout`, provenance=`structure_only`, verification=`not_clinically_verified`와 같은 출처/제한 필드를 검토한다.
- UI의 외관은 레퍼런스가 될 수 있지만, 실제 nU 화면의 정확한 복제라고 주장하지 않는다.
