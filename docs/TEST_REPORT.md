# 시뮬레이터 v0.2 검증 기록 (2026-10-10)

## 검증 환경
- Node.js 22, 테스트 스크립트 `tests/domain.test.js`
- Chromium + Playwright(시스템의 네트워크·파일 페이지 접근 정책으로 `about:blank`에 HTML/CSS/JS 삽입하여 사용자 입력을 시뮬레이션); 실제 HTTP/파일 URL 브라우징 테스트는 **미실시**

## 확인 결과
- 도메인 단위 테스트 15/15 통과: 환자/목록 분리, 검색/분류, 근무조 로그인, 임시 저장·비밀번호 재인증·거절, 유형 혼동 차단, 환자 별 요약, 수행/기록 독립 집계, 데이터 유효성.
- 브라우저 상호작용 검사 1개 종합 시나리오 통과: 4명 환자 렌더링, 38개 후보 검색, 미로그인 저장 차단, 로그인, 임시저장, 잘못된 비밀번호 거절, 재인증 확정, 모의 수행/기록 작성, 가상 환자 변경 시 데이터 격리, 로컬 저장 데이터 생성.
- 브라우저 JS 오류: 종합 시나리오에서 0건.

## 한계
- 실제 병원 nU의 동작이나 로그인·세션·계정 권한을 검증한 것이 아님.
- 비밀번호는 스크립트에 포함된 합성 데모 PIN이므로 보안 기능이 아니라 재인증 UX 데모. 실제 시스템에 사용하면 안 됨.
- LocalStorage는 단일 브라우저 저장소이며 보안·감사·다중사용자 접근제어/동시편집을 제공하지 않음.
- 실제 기관의 간호처방 등록 권한, 수행/기록 정책, 의학적 타당성은 검증하지 않음.
- 데이터 저장/복원은 함수 수준 및 상호작용 중 로컬 저장을 확인했으나 해당 테스트는 페이지를 다시 로드한 완전한 브라우저 재시작 시험은 아님.
- 화면은 언제든 교체 가능하며, 도메인 데이터/로직과 UI 코드를 파일로 구분함.
