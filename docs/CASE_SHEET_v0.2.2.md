# v0.2.2 가상 Kardex · 간호처방지 조회 기능 설계 및 구현

작성: 2026-10-10 · 간호처방 시스템 단독 개발 · **실제 nU/EMR 아님**

## 개발 목적과 범위
- PRN/MICU와의 자동 연결 없이 **간호처방 시스템 자체**에 환자별 사례(Kardex식 인계 요약)와 시간별 간호처방지(Order Manage 형식) 조회를 제공한다.
- 기존 **ACT 38개·환자 4명·초기 주문 16건**, 간호사 로그인/모의 PIN 재인증/수행·기록/그룹화/로컬 저장은 보호한다.
- 교내 `icn 워크리스트.pdf`(12쪽), `2026사례기반 실무실습 사례자료.pdf`(17쪽)의 **시나리오→Kardex→처방지** 정보 흐름과 표의 정보 배치를 참고한다. 학교 원문·환자 식별자·처방코드·약물 용량은 복제하지 않는다.

## 신규 구성
- `app/case-context.js`: 4개 환자 ID별 **완전 합성** 시나리오 제목, 인계 사항, 관찰 초점, 관련 학습 술기. 기존 `fixtures.js` 환자/주문 데이터를 변경하지 않는다.
- `app/order-sheet-model.js`: 원본 상태를 **읽기 전용으로** 투영하는 순수 함수. `validateCases`, `buildContext`, `buildSheet` 제공.
- `app/index.html`, `app/app.js`, `app/styles.css`: '처방·수행·기록 현황' 위쪽에 **접이식** '가상 Kardex · 간호처방지' 패널 추가. 기본 닫힘. 기존 처방·수행·기록 화면은 그대로 유지한다.
- `tests/order-sheet.test.js`, `tests/order_sheet_browser.py`: 사례 참조 무결성, 환자별 격리, 처방 ID 유지, 상태 및 건수 집계, 합성 HTML 상호작용 시험.

## 데이터/표시 규칙
1. 환자 `P-A101` 등이 원본이며 케이스 컨텍스트는 `patientId`로만 연결한다. PRN 환자 `DEMO-P*` 등과 자동 매핑하지 않는다.
2. 간호활동 후보 `SIM-ACT-*` 코드는 **카탈로그 ID**, `DEMO-O-*` 및 `O-*`는 개별 **가상 간호처방 ID**이다. UI에서 두 열로 분리한다.
3. 작성자 `orderedBy`와 확인자 `checkedBy`는 서로 구별한다. 확인자 필드가 있어도 실제 전자서명·독립 2인 확인을 의미하지 않는다.
4. 처방 생성시각 `createdAt`, 상태 `draft/confirmed/held/cancelled`, 수행 이벤트 건수, 기록 건수는 각 원본 객체에서 계산하며 **기록 누락을 단순 차감으로 추정하지 않는다**.
5. 행은 **환자 + 작성 로컬일시 + 가상 작성자 + 자료 출처(초기 사례/추가 모의)** 기준으로 화면에서 그룹화한다. 같은 시간대/활동인 행도 **개별 주문 ID는 보존**한다.
6. 시드 `DEMO-O-*`는 '초기 합성 사례', 새 `O-*`는 '추가 모의 처방'이라는 **데이터 출처 구분**이다. 실제 의료기관의 정규/추가 처방 또는 임상 우선순위를 재현하지 않는다.
7. ACT 간호행위에 해당하지 않는 투약 용량·경로·1회량 등은 **계산하거나 자동 생성하지 않는다**. `FOLLOW`, `MAT`, 검사/검체/검체 용기는 별도 객체로 남는다.
8. 마스터/개별 처방/수행/기록을 **읽기 전용 뷰**에서 재구성할 뿐, 원본 상태·localStorage 키 `nursing-order-demo-v02`/스키마 `2`는 변경하지 않는다.
9. 환자별 시나리오 문장은 의무기록이나 임상 권장사항이 아니라 **가상 상태 및 UX 모의 과제**다.

## 신뢰성과 UX
- 패널 기본 닫힘으로 기존 화면을 방해하지 않는다. 추후 완전 다른 UI로 교체하더라도 순수 `order-sheet-model.js`를 재사용할 수 있다.
- 표가 길면 **표 영역만 가로 스크롤**하며, 주요 표시값은 `escapeHTML` 처리하여 임의 입력 문자열이 HTML로 실행되지 않게 한다.
- 환자 전환·추가 모의 처방·재인증 이후 새로 계산하여 보여준다. 별도 저장 또는 동기화 이벤트를 만들지 않는다.
- 외부 의사처방 참조·공통 직원/환자 ID·자동 간호행위 생성·MICU 근무표 연결 **미구현**; 세 앱을 독립 유지한다.

## 향후 독립적 다음 개발 후보
1. 동일 ACT 후보에 대해 시행 부위·목적·빈도 같은 **가상의 구조적 상세조건**을 별도 메타데이터로 검토(기존 저장 스키마 호환 설계 선행).
2. 처리 상태 변경/취소/정정과 이력 정합성 검토(지금은 확정 및 수행·기록 추가 중심).
3. 인계 요약의 관찰정보·시간 순서·수행 사건 연결(기록에 근거하지 않은 상태 자동 추정 금지).
4. 세 프로젝트 통합은 당분간 추진하지 않고 설계 문서로만 호환성 고려.
