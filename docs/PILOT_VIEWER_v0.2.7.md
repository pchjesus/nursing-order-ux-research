# v0.2.7 — 읽기 전용 합성 파일럿 평가 뷰어

작성 기준: 2026-10-12 · **연구도구만 추가**, 기존 간호처방 MVP는 v0.2.6 그대로.

## 왜 이번 개발인가?

v0.2.6의 보류·취소·연기 모델은 기술적으로 검증되었지만 **실제 nU에 없는 기능인지, 유용한지, 간호사의 권한과 일치하는지 확인하지 못했다**. 따라서 업무 규칙을 추가하지 않고, 기존 `research/pilot-case-model.cjs`의 합성 과제를 브라우저에서 직접 조회해 **사용성 평가 설계를 검토**할 수 있도록 한다. 이는 기존 앱 재설계나 비교 실험 결과가 아니라 독립된 파일럿 도구다.

## 실행

저장소 전체를 내려받아 **`research/pilot-viewer.html`을 브라우저에서 열기**. 인터넷·서버·로그인 불필요. 앱 기존 화면은 `app/index.html`; 파일럿은 별도 경로이므로 원본 앱 화면과 혼동하지 않는다.

## 기능

- **A1/A2 (탐색):** v0.2.6과 동일한 ACT 42개·도메인 검색 함수를 사용해 '드레싱' 및 가상 코드 `SIM-ACT-0053` 검색, 관련 유사 후보 확인.
- **B1 (동일 코드의 개별 처방):** 환자 A에서 `SIM-ACT-0053`인 `PILOT-O-001`(조건부, 예정 미정)과 `PILOT-O-002`(8시간 간격, 예정 3개)를 별도 ID로 표시. 코드 그룹화는 켜고 끌 수 있으며 **데이터 합치기는 없음**.
- **C1/C2 (수치):** 예정 슬롯 3개·모의 수행 사건 1건·연결 기록 0건을 각각 표시. `PILOT-O-001`의 조건부 예정 횟수는 0이 아니라 **미정(null)**.
- **D1 (환자 격리):** 환자 A/B 전환. 환자 B는 `PILOT-O-003`만 보이며 A의 수행 이력을 공유하지 않음.
- 연구자용 예상값은 **기본 숨김**. 평가 대상자에게 보이는 결과를 사전에 유도하지 않도록 과제별 보조 문구만 제공.
- 페이지에는 처방·수행·기록 생성, 계정 인증, 사용자 입력 결과/참여자 답변 수집 기능을 추가하지 않음. 화면 상호작용은 검색어·환자·표시 그룹화 변경만 처리.

## 모델·저장 계약

- `research/pilot-viewer-model.js`: UMD 기반의 읽기 전용 사례 모델. 기존 `research/pilot-case-model.cjs`와 **동일한 합성 state**를 생성하는지 Node 검사로 대조.
- `research/pilot-viewer-ui.js`: 화면 표시 전 상태 JSON의 불변성을 검사. 환자 선택과 검색·그룹화 후에도 원본 불변.
- 별도 HTML에서 현행 `../app/fixtures.js`, `../app/activity-details.js`, `../app/domain.js`를 로드하되 **`app/app.js`는 로드하지 않음**. 따라서 기존 로그인, `nursing-order-demo-v02` localStorage 불러오기/쓰기, 기존 환자 처방 변경 작업과 독립.
- 브라우저 페이지 자체는 localStorage/sessionStorage/fetch 호출, 양식 제출 또는 참가자 반응 기록을 사용하지 않음.
- 원본 자료 315개 분류, ACT 42개, 환자 4명, 시드 처방 16건, 제품 18개, 스키마 2, 실제 MVP의 UI/JS/CSS, PRN/MICU 프로젝트 모두 **수정하지 않음**.

## 검증 기준

1. 기존 Node 116건 및 Chromium 브라우저 7개 회귀 유지.
2. 신규 읽기 전용 모델 12건: 기존 CLI 사례와 전체 객체 정합성, 코드 검색, 그룹 구분, 건수, 환자 격리, 불변성, 스토리지 사용 금지.
3. 신규 Chromium 사례 1개: 실제 `file://` 페이지 열기, A1/A2 검색, 42개 초기화, 환자 전환, 그룹 토글, 동결된 소스 의미, storage 접근을 차단해도 렌더링 유지, 미처리 JS 오류 0.
4. 브라우저가 그린 연구 뷰어 실제 스크린샷을 CI artifact로 저장해 향후 평가 디자인 검토에 활용.

**실제 자동검사 통과 여부는 GitHub Actions 실행 로그 확인 후 별도로 기록한다.**

## 남아 있는 Gate 0 및 한계

- 실제 간호처방 범위, 기존 nU 검색/그룹/반복/기록 UI, 업무 권한, 중복 기능 여부의 정식 확인은 **미실시**.
- 이 파일럿 뷰어의 화면과 기존 MVP의 화면은 동일하지 않다. 같은 시나리오로 **검증된 A/B 실험이나 시간 단축 효과를 주장하지 않는다.**
- 사용자 대상 소요시간·오선택률 등 실제 사용성 데이터를 수집하지 않았다. 향후 참가자 모집·개인정보 보호·기관 검토가 필요한 경우 절차를 먼저 확인한다.
- 임상적 판정, 의료기관 인증, 간호처방 발행 권한, 기록 완료·누락 여부를 실습 사례만으로 추론하지 않는다.
- 다음 중요한 UX 선택(메인 화면 비교 배치·진행 정보, 차트 시각화, 근무조별 일정)은 기존 실제 업무 확인/사용자 결정 이후 시행한다.
