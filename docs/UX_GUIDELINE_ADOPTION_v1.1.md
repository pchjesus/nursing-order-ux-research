**우선순위:** 실환자/실기관 자료 금지 및 승인된 합성 데이터·도메인 객체·상태/저장 계약 > 저장소별 승인 UX/업무 구조와 B+ 절차 > 범용 시각 디자인 권고. 충돌하거나 중요한 UI 기획을 바꾸는 경우 대안을 보고하고 사용자 승인을 받는다.

## 연구 목적에 맞춘 적용 항목

- **정보 구조:** 기존 승인된 A–C–C 방향(간호활동 ACT 우선, 처방 전후 연결, 업무 단계별 상위 화면 + 임상 목적별 하위 분류)을 출발점으로 삼는다. 검색·카테고리·유사어·구별 속성의 탐색이 쉬워야 하지만 코드/임상적 의미를 UI가 임의로 동등화하지 않는다.
- **원본 구별:** `order_instance`(개별 처방), `execution_event`(수행), `documentation_record`(기록)를 별개로 유지한다. 여러 주문을 카드로 요약하더라도 원본 ID, 환자 분리, 상태·예정/수행/기록 건수·시각·감사 이력은 보존한다.
- **교육용 투명성:** `SIM-*` 가상 코드, 검증 전 제품 후보와 실제 병원 nU/공식 코드 및 실제 임상 지침을 명확히 구별한다. 가상 수행·재인증·보류/취소의 표시를 실제 병원 정책으로 암시하지 않는다.
- **상태 및 저장:** `nursing-order-demo-v02` localStorage 키, 현재 schema 2, 기존 작성/수정/삭제/되돌리기·환자 전환 동작을 기존 계약대로 보호한다. 저장 키/스키마 변경은 이전 버전 자료에 대한 읽기 호환·마이그레이션·실패 복구·구버전 회귀 사례 검증을 선행한다.
- **연구용 뷰어:** `research/pilot-viewer.html`은 기존 메인 앱과 별개의 읽기 전용 합성 평가 도구이다. 원본 시뮬레이터를 강제로 병합하거나 뷰어의 권한·저장 의미를 바꾸지 않는다.
- **접근성/표현:** 한국어 용어·긴 코드·표/링크의 줄바꿈과 320/360/390px·태블릿·데스크톱, 키보드 포커스, 200% 텍스트 확대, 320 CSS px 해당 리플로우, 색상 외 상태 단서를 점검한다. 저밀도 미학을 위해 비교해야 할 수행·기록·상태를 숨기지 않는다.

## 후속 개발 검토 게이트

1. 최신 `main` 코드·승인된 UI/데이터 계약·미확정 결정을 확인하고, 대표 사용자 작업과 위험(L/M/H)을 적는다.
2. 설계 대안에서 **탐색 성공·유사 처방 구별·처방/수행/기록 정합성**을 평가하고, 의미 있는 UX 선택은 사용자 승인을 받는다.
3. 변경 범위에 맞는 Node/Chromium 테스트, 저장/재진입 및 이전 데이터 호환성, 키보드·반응형을 검증한다. B+ 정책의 릴리스 검증 조건을 임의 축소하지 않는다.
4. 실제 자동검사 / 브라우저 / 실기기 / 현직 간호사 사용성 / 임상 전문가 평가를 각각 PASS·FAIL·NOT RUN·N/A로 기록한다. 가상 시나리오의 기술적 성공을 실제 임상 효용으로 확대하지 않는다.

**이번 등록 범위:** 문서·링크만 추가하며 앱 UI, 검색/도메인 로직, 합성 카탈로그·환자/처방, 저장 구조, 테스트·CI는 불변이다.
