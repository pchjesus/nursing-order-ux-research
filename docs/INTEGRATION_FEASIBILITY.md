## 2. 추천 방향: 독립 모듈을 유지한 읽기 전용 계약

1. **1단계(가장 안전):** 가상 MICU 근무표에서 `date`, `duty`, `staffId`, `displayName`, `role`만 **버전 있는 파일 형태**로 내보내기(향후 구현); 간호처방 앱에서 검증·미리보기·사용자 승인 후 읽기 전용으로 사용. 실제 사람 이름이 포함된 업무용 근무표를 데모로 이동하지 않는다.
2. **2단계:** 두 앱이 사용하는 `sharedStaffId` 매핑(동명이인/근무표 교체/동일 직원 여러 달)을 별도 구성. 근무표상 근무자 표시 ≠ 현재 세션 로그인 ≠ 처방자/확인자 인증. **근무표를 이용한 자동 로그인 금지**.
3. **3단계:** 가상 환자 레지스트리에서 대피에 필요한 **최소 정보만** 별도 명시된 목적 하에 주고받도록 새 대피 환자 모듈 설계. 병력·간호기록·개별 처방을 통째로 MICU 쪽에 복제하지 않음.
4. **장기:** 실제 다중 사용자 통합을 희망하면 공유 백엔드, 직원/환자 식별 체계, 서버 인증/권한, 감사기록, 통신·저장 암호화, 동시 수정 처리, 개인정보·기관 승인 및 임상 검증이 먼저 필요함.

### 예시 교환 계약(제안, **미구현**)

```json
{
  "schemaVersion": "roster-simulation-v1",
  "source": "synthetic-micu-roster",
  "exportedAt": "2026-10-10T09:00:00+09:00",
  "rosterId": "SAMPLE-2026-10",
  "date": "2026-10-10",
  "duty": "D",
  "staff": [{"sourcePersonId": "sample:1", "sharedStaffId": null, "displayName": "가상 간호사 1", "role": "nurse"}]
}
```

필드의 필수 여부, 개인정보 제거 정책, 서명/검증값, stale-data 기준, 실제 전달 UI는 후속 승인 전 확정하지 않는다. **실제 MICU 백업 전체 JSON을 간호처방 앱에 임의로 읽혀서는 안 됨.** 백업은 근무표·수동 수정·감사정보까지 포함한다.

## 3. 환자정보 역방향 연계의 범위

| 가상 간호처방 데이터 | MICU 대피 모듈로의 전달 제안 | 이유 |
|---|---|---|
| 환자 식별자, 병상, 위치 | 목적과 접근권한을 확인한 뒤 최소 전달 검토 | 대피 대상 식별 |
| 대피 이동 보조 필요 여부 | **독립적으로 검증·입력된 대피 평가**만 전달 | 간호처방 내역에서 안전하게 자동 추론 불가 |
| 특정 기기 지원 필요 | 명시적 대피 계획 데이터만 전달 | 현재 처방 유무로 기기 의존성을 판정하면 위험 |
| 상세 병력, 의무기록, 처방 전체 | 기본적으로 전달하지 않음 | 대피 기능에 불필요한 민감정보 축적 방지 |
| 담당자·근무조 | 승인된 직원 식별자/유효 시간 범위에 한정 | 변경된 근무표·동명이인 위험 |

## 4. 위험 및 대책

| 위험 | 심각도(설계 검토) | 예방 조건 |
|---|---|---|
| 실제 근무표 이름을 환자/가상 계정과 잘못 연결 | 높음 | 안정 직원 ID 매핑·수동 검토·동명이인 반례 |
| 근무조를 근거로 자동 로그인·처방 확인자 부여 | 높음 | 근무 여부와 인증된 사용자 계정 엄격 분리 |
| 처방항목으로 대피 이동능력/산소 필요 추론 | 높음 | 별도 검증된 대피 평가 필요, 자동 판단 금지 |
| IndexedDB 원본 DB 파손·다운그레이드/복원 충돌 | 높음 | MICU 앱의 읽기 전용 어댑터, 구조 변경 금지, 회귀 테스트 |
| 환자 임상 정보와 근무자 개인정보 과다 공유 | 높음 | 합성 데이터 우선, 최소 정보 원칙, 역할별 접근 |
| 서로 다른 출처의 브라우저 저장소 접근 실패 | 중간 | JSON 데이터 계약 또는 인가된 서버 API, 직접 스토리지 열람 회피 |
| 근무표 수정/삭제로 연계 데이터 노후화 | 중간 | 출처/버전/작성시각 및 유효기간 검사, 구버전 경고 |
| 두 앱의 저장 시점이 달라 모순 발생 | 높음 | 연동 데이터는 먼저 조회 전용, 충돌·동기화 전략 수립 후 쓰기 허용 |

## 5. 다음 단계 진입 조건

- **연동 구현 전:** 가상 근무표 스키마/이름-ID 매핑 규칙, 노후화 판단, 오류와 백업 정책을 문서로 합의.

- **환자 대피 모듈:** 대피에 필요한 항목과 책임자·검증 권한을 확정한 뒤 설계. 비임상 상황에서만 테스트.
- **실제 연동:** 별도 기관 승인, 개인정보·보안·실무 검증 전에는 수행하지 않음.
