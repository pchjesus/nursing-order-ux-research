## 신규 테스트의 핵심 검증
1. 기존 ACT 38개 보존 및 기존 `CATALOG`에서 네 개의 추가 코드를 가져왔음을 비교.
2. 10개 카테고리의 42개 활동마다 구조화된 선택 옵션 존재.
3. 듀오덤 검색 → ACT 후보 → 부위/목적/빈도/방법/제품 선택 → 개별 처방에 저장.
4. 유량조절기형/인퓨전 펌프 전용세트 후보 분리; 잘못된 방법–제품군 조합 거절.
5. CVC 삽입부 드레싱 관련 참고 제품 범위 제한; 단순 관찰 활동에 제품 강제 선택 안 함.
6. 실제 제품명은 제조사 자료를 확인했으나 제품 사용 가능성/호환성을 단정하지 않음.
7. 임시저장 → 잘못된 PIN 거절 / 동일 계정 정상 재인증 → 개별 작성자/확인자 보존.
8. 기존 레코드는 새 `details` 없이도 로딩, 원본 상태 스키마/키 변경 없음.
9. 저장 데이터를 직렬화→새 DOM/모의 localStorage에 주입→다시 렌더링해 선택한 제품 및 상세 조건 복원 확인.
10. 환자 전환 시 앞선 환자의 세부 조건과 제품이 다른 환자 목록에 보이지 않음.
11. 새 간호처방 세부 조건은 기존 그룹화에서 개별 ID별로 보존되고, 읽기 전용 Kardex/처방지에도 표시.
12. 개발자 화면 검사에서 감지된 미처리 JS 예외 없음.

## 한계
- 웹 브라우저를 실제 HTTP localhost 주소 또는 `file://`로 여는 전체 통합 환경 검사는 이 실행 환경에서 제한되어, Chromium의 합성 페이지에 HTML/CSS/JS를 주입해 검증함.
- 실제 디스크의 localStorage 복원/병원 PC 브라우저 및 여러 기기 동기화는 확인하지 않음. 새 DOM/메모리 기반 저장 JSON 복원까지 확인.
- 사용자 검수와 사용성 시험은 사용자의 이전 결정대로 MVP 안정화 시점까지 보류.
- 실제 병원 nU, 처방 가능 권한, 장비/수액세트 호환성, 실제 제품 유통, 임상 적응증·효과 검증은 **수행하지 않음**.
- 제품의 기종과 포장규격, 수액 속도/약물투여량, 처방 간격은 자동으로 결정하지 않음.
